### 2. Trending Simulations Feed

**Type:** Feature / Growth
**Effort:** Small (hours)
**Impact:** The MiroShark homepage currently shows nothing about what others are simulating. A new visitor lands on the topic input form with no social proof, no discovery hook, no sense that other people are actively using this. `GET /api/trending` returns the 10 most recently published simulations with their topic, direction, confidence, and a timestamp — a live "what's happening right now" feed. The homepage (or Step1 topic input) gains a "Trending now" panel: a scrolling list of recent topics like "EU AI Act enforcement · BULLISH · 73%" and "2026 Fed rate decision · BEARISH · 81%". Two effects: (1) new users see social proof instantly — real topics, real results, someone ran this recently; (2) the topic list is a discovery mechanism — users often don't know what to simulate, and seeing "others simulated X" is the best prompt. Builds on existing activity feed (Jun 9) and search service (Jun 14) infrastructure. Zero new data storage — reads the same `signal.json` files that already exist. During a 46-day social silence, the trending feed is the *internal* proof-of-use that makes the product feel alive to every new visitor.

**How:**
1. Create `backend/app/api/trending.py` (~70 LoC, pure stdlib). `GET /api/trending?limit=N&window=Xh`. Params: `limit` (default 10, max 50, clamped), `window` (hours; default 168 — 7 days; if fewer than 5 simulations in window, expand to 30 days, then all-time). Scans the simulations base directory: for each directory containing `signal.json`, read `topic`, `direction`, `confidence_pct`, `created_at`, `simulation_id`. Filter to published simulations only (check `published: true` in signal.json, or adapt to whatever the publish gate actually checks — inspect one real signal.json to confirm). Sort by `created_at` descending. Return top N. Response: `{"generated_at": ISO8601, "window_hours": int, "total_in_window": int, "trending": [{"simulation_id": str, "topic": str, "direction": "BULLISH"|"BEARISH"|"NEUTRAL", "confidence_pct": float, "created_at": ISO8601, "url": "https://miroshark.xyz/sim/{id}"}]}`. `Cache-Control: public, max-age=300` (5-minute cache — fast enough for "trending" to feel live). Register at `GET /api/trending`. Add to `surfaces_catalog.py`. Update `docs/API.md` with a "Discovery" section: `GET /api/trending` and `GET /api/simulation/search?q=...` side by side.

Clicking a topic pre-fills the Step1 topic input with that exact topic string — lowering the barrier to first simulation. If `/api/trending` returns fewer than 3 results, hide the panel silently (don't show "no trending simulations" to new users — that's the opposite of social proof). ### 3. Simulation Narration API

**Type:** Feature / DX
**Effort:** Small (hours)
**Impact:** MiroShark produces rich structured data — trajectory.json, actions.jsonl, signal.json — but there is no human-readable summary of what actually happened in the simulation. A policymaker who receives a share link reads "BULLISH · 73%" and needs to understand why, but the raw JSON is inaccessible without technical knowledge. Journalists, product managers, and non-developer decision-makers are the audience for a narrative: "Over 5 rounds, the 20-agent swarm began with deep disagreement on climate tax policy (32% bullish). By round 3, Agent-7's introduction of the EU Carbon Border Adjustment Mechanism data shifted 4 neutral agents to bullish. Final consensus: 73% bullish with high confidence." `GET /api/simulation/{id}/narration` generates this narrative from template-based rendering of existing data — no new LLM calls, no API costs, pure computation. Reads `trajectory.json` for round-by-round belief evolution, `signal.json` for the final direction and confidence, and a representative sample of `actions.jsonl` for the most-cited arguments. Template slots: opening (topic + agent count + rounds), turning point (round with the largest single-round bullish_pct change), final stance (direction + confidence + dissenting minority if confidence < 70%), and a one-sentence coda (the dominant argument from the last round). The narrative is the shareable artifact for audiences who can't read JSON — and it's the missing piece that turns a simulation result into a blog post section, a Slack message, or a press quote.

**How:**
1. Create `backend/app/api/narration.py` (~120 LoC, pure stdlib). `GET /api/simulation/{id}/narration`. Publish-gated. Reads three files from the simulation directory: `signal.json` (topic, direction, confidence_pct, agents, rounds), `trajectory.json` (per-round belief evolution — array of `{round, bullish_pct, neutral_pct, bearish_pct}`), and a sample from `actions.jsonl` (first and last 5 lines — check actual field names in one real simulation directory; likely `round`, `agent_name`, `action_type`, `content`). Computes: **turning point round** — the round with the highest absolute delta in `bullish_pct` from the prior round (or `bearish_pct` if BEARISH direction); **opening_bullish_pct** — `trajectory[0].bullish_pct`; **peak_shift** — the delta at the turning point round; **final_direction_word** — "bullish" / "bearish" / "divided" (use "divided" when confidence_pct < 55%); **minority_pct** — the largest of bearish_pct or bullish_pct in the final round that opposes the direction (for "73% bullish · 27% bearish"). Assembles a 3–4 sentence narrative from a template: `f"Over {rounds} rounds, {agents} agents debated '{topic}'. The swarm opened at {opening_bullish_pct:.0f}% bullish. {f'By round {turning_point}, a shift of {peak_shift:+.0f} percentage points brought the group toward consensus.' if abs(peak_shift) >= 5 else 'Sentiment moved steadily across all rounds.'} Final result: {direction} with {confidence_pct:.0f}% confidence{f' ({minority_pct:.0f}% remained opposed)' if minority_pct > 20 else ''}."` Graceful fallback: if trajectory.json is absent or malformed, return a shorter template using only signal.json fields. Response: `{"simulation_id": id, "topic": str, "narration": str, "word_count": int, "generated_at": ISO8601}`. `Cache-Control: public, max-age=86400` (narrative is deterministic and cacheable). Register at `GET /api/simulation/{id}/narration`. Add to `surfaces_catalog.py`. Update `docs/API.md`.

2. Add a "Summary" section to the simulation share page (`Step3Simulation.vue`): displayed above the direction/confidence result card, a 3–4 sentence plain-English paragraph fetched from `GET /api/simulation/{id}/narration`. No headline — the narration IS the headline, styled as a blockquote or lead paragraph (`font-size: 1.1rem; color: #ccc; font-style: normal`). Include a "Copy summary" button (clipboard API) — this is the one-click artifact for journalists and PMs who need to paste the result into an email. Also expose the narration in the embed dialog as a "Plain-language summary" section that includes the full narration text as a copyable `<pre>` block. No additional unit tests for the UI component — test the backend logic only.

3. Add 5 unit tests: published simulation with full trajectory.json returns 200 with `narration` as a non-empty string; narration contains the topic string; narration contains "bullish" or "bearish" or "divided"; simulation with missing trajectory.json falls back to signal.json-only template and still returns 200; unpublished simulation returns 404. Log to memory: "Simulation Narration API created 2026-08-22. `GET /api/simulation/{id}/narration` — template-based prose narrative, no LLM calls. Reads trajectory.json (turning point detection: largest round-delta in bullish_pct), signal.json (direction/confidence), actions.jsonl (first+last 5 lines). 3–4 sentence output: opening stance, turning point shift, final direction + minority %. Fallback: signal.json-only template when trajectory absent. Step3: blockquote lead paragraph + 'Copy summary' button. Addresses non-technical audience accessibility gap."

### 4. Daily Digest Report Endpoint

**Type:** Feature / DX
**Effort:** Small (hours)
**Impact:** Teams and operators who run multiple MiroShark simulations per day have no consolidated view of what ran. `GET /api/digest/daily?date=YYYY-MM-DD` scans all simulations completed on that calendar date and returns a structured Markdown report: a one-line header, a summary table (topic | direction | confidence | time), aggregate stats (total simulations, bullish/bearish/neutral split, average confidence, combined cost estimate), and a "Notable findings" section that surfaces the highest-confidence and most-contrarian results. Operators can pipe this to a Slack webhook, email it as a newsletter, or commit it to a research repo — it's the daily audit trail that enterprise teams expect before adopting any SaaS tool. Builds on the activity feed (Jun 9) and cost receipt API logic but formats the output as a human-readable Markdown document rather than a JSON array. `GET /api/digest/weekly?date=YYYY-MM-DD` (returns the ISO week containing the date) is a two-line extension of the same logic. Zero new data storage — pure computation over existing `signal.json` files. Useful for the operator deploying MiroShark for a research team: instead of building their own aggregation script, they call this endpoint and get a paste-ready report.

**How:**
1. Create `backend/app/api/digest.py` (~110 LoC, pure stdlib). Two endpoints: **`GET /api/digest/daily?date=YYYY-MM-DD`** and **`GET /api/digest/weekly?date=YYYY-MM-DD`**. Date validation: if `date` param absent, default to today (UTC). If malformed, return 400 `{"error": "invalid_date", "expected_format": "YYYY-MM-DD"}`. Date range logic: daily = all simulations where `signal.json.created_at` falls on that calendar date (UTC); weekly = all simulations in the ISO week (Mon–Sun) that contains the given date. For each simulation in range: read `signal.json` for `topic`, `direction`, `confidence_pct`, `created_at`, `simulation_id`, `cost_usd_total` (null if absent). Sort by `created_at` asc. Compute aggregates: `total`, `bullish_count`, `bearish_count`, `neutral_count`, `avg_confidence_pct` (round to 1 decimal), `total_cost_usd` (sum, null if any cost data missing), `highest_confidence` (simulation_id + topic + direction + confidence_pct), `most_contrarian` (lowest confidence_pct). Format as Markdown: `# MiroShark Daily Digest — {date}\n\n**{total} simulation(s) completed**\n\nDirection split: {bullish_count} BULLISH · {bearish_count} BEARISH · {neutral_count} NEUTRAL\nAverage confidence: {avg_confidence_pct}%\n{f'Total cost: ${total_cost_usd:.4f}' if total_cost_usd else ''}\n\n## Results\n\n| # | Topic | Direction | Confidence | Time |\n|---|-------|-----------|------------|------|\n{table_rows}\n\n## Notable\n- **Highest confidence:** {highest_confidence.topic} — {highest_confidence.direction} {highest_confidence.confidence_pct:.0f}%\n- **Most contrarian:** {most_contrarian.topic} — {most_contrarian.direction} {most_contrarian.confidence_pct:.0f}%\n`. If `total == 0`, return `{"date": date_str, "total": 0, "report": "# MiroShark Daily Digest — {date}\n\nNo simulations completed on this date.\n"}`. Response: `{"date": str, "period": "daily"|"weekly", "total": int, "report": str (Markdown)}`. `Content-Type: application/json`. Also support `Accept: text/markdown` header — if present, return the Markdown string directly with `Content-Type: text/markdown; charset=utf-8`. `Cache-Control: max-age=3600` for past dates; `max-age=60` for today (still accumulating simulations). Register at `GET /api/digest/daily` and `GET /api/digest/weekly`. Add both to `surfaces_catalog.py`.

2. Add a CLI usage example to `docs/API.md`: `curl https://miroshark.xyz/api/digest/daily?date=2026-08-22 -H 'Accept: text/markdown' | pbcopy` — copy today's digest to clipboard. Add a `scripts/daily-digest.sh` example: `curl ... | gh gist create --filename "miroshark-$(date +%Y-%m-%d).md" -` — publishes the daily digest as a private GitHub Gist with one command. This script doubles as a community showcase: operators who share their daily gist links are organic social content. Update `README.md` with a "For Teams" section: "Running multiple simulations a day? `GET /api/digest/daily` delivers a consolidated Markdown report — pipe to Slack, email, or commit to your research repo."

3. Add 5 unit tests: `GET /api/digest/daily?date=2026-01-01` returns 200 with `total >= 0` and `report` as non-empty string; report contains "Daily Digest" and the date string; `Accept: text/markdown` header returns `Content-Type: text/markdown`; `GET /api/digest/weekly?date=2026-08-22` returns a report covering Mon Aug 17 – Sun Aug 23; invalid date returns 400 with `expected_format` field. Log to memory: "Daily Digest Report Endpoint created 2026-08-22. `GET /api/digest/daily?date=YYYY-MM-DD` + `GET /api/digest/weekly?date=YYYY-MM-DD`. Returns Markdown report: direction split, avg confidence, cost total, results table, highest-confidence + most-contrarian highlights. `Accept: text/markdown` returns raw Markdown. Cache: past dates 1h, today 60s. `scripts/daily-digest.sh` example: pipe to GitHub Gist. For teams running multiple simulations per day."

## Selection Rationale

Five ideas targeting the Sep 1 locale deadline, post-rally social engagement gap, operator tooling, and viral GitHub discovery.

- **Hindi (HI) Locale (#1)** — With 10 days to the Sep 1 five-language hyperstition deadline and GH_GLOBAL blocking 8 queued locale PRs, Hindi is the next clean LTR path: 13M+ Indian GitHub developers, IndiaAI Mission policy hook, Devanagari script (no RTL changes). EN + ZH-CN + DE + FR + HI = 5/5 the day GH_GLOBAL restores.

- **Trending Simulations Feed (#2)** — 153 distinct buyers entered yesterday, and none said anything publicly. The trending feed is the internal social-proof signal that makes the product feel alive to every new visitor: "Recently simulated: EU AI Act enforcement · BULLISH · 73%". Topic pre-fill on click reduces first-simulation friction. Builds on existing activity feed and search infrastructure.

- **Simulation Narration (#3)** — The biggest audience for the Aug 21 rally is non-technical: traders, journalists, policy researchers. They can't read trajectory.json. A 3–4 sentence plain-English narrative ("By round 3, a 14-point shift in bullish sentiment...") is the paste-ready artifact for Slack, email, and press quotes.
