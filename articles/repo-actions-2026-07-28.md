### 4. Academic Citation Helper

**Type:** Growth / DX
**Effort:** Small (hours)
**Impact:** The "academic citation by September 1" hyperstition has zero infrastructure. A paper cannot cite MiroShark today without inventing citation metadata from scratch. The CITATION.cff format is GitHub's native citation standard — when a repo contains `CITATION.cff`, GitHub renders a "Cite this repository" button in the sidebar that outputs BibTeX and APA automatically. Academic researchers (the "peer-reviewed citation" audience) rely on this button for citation imports directly into Zotero, Mendeley, and LaTeX. Beyond the GitHub button, a `/api/cite` endpoint lets researchers cite individual simulation results in the format their journal requires — BibTeX for CS venues, RIS for most social science journals, Chicago for policy papers. The combination of `CITATION.cff` (repo-level) and `/api/cite` (per-result) covers both the "used MiroShark as infrastructure" citation and the "analyzed simulation result X" citation — two distinct academic use cases. Neither requires GH_GLOBAL (CITATION.cff is a file commit to the watched repo; `/api/cite` is a backend endpoint). This is a zero-maintenance, permanent addition that makes MiroShark formally citable the moment any researcher lands on the repo page.

**How:**
1. Create `CITATION.cff` in the MiroShark root. Format (CITATION.cff v1.2.0): `cff-version: 1.2.0`, `message: "If you use MiroShark in your research, please cite it using the metadata in this file."`, `title: MiroShark — Universal Swarm Intelligence Simulation Engine`, `abstract: "An open-source multi-agent swarm intelligence engine that simulates crowd opinion dynamics across configurable platforms and agent archetypes. Designed for social science research, market analysis, and public policy modeling. Simulations run in under 10 minutes for under $1 USD."`, `version: 0.1.0` (use the actual version from pyproject.toml/package.json), `date-released: YYYY-MM-DD` (actual first public release date from git log), `license: MIT`, `repository-code: https://github.com/aaronjmars/MiroShark`, `url: https://github.com/aaronjmars/MiroShark`, `keywords: [swarm-intelligence, opinion-dynamics, multi-agent-simulation, social-simulation, AI-agents]`, `authors: [{family-names: Mars, given-names: Aaron, alias: aaronjmars}]`. Add a "## Citing MiroShark" section to `README.md` (below Contributing) that explains the GitHub "Cite this repository" button, shows an inline BibTeX block, and links to `/api/cite` for simulation-specific citations.
2. Add `GET /api/simulation/{id}/cite` to the backend (`backend/app/api/simulation.py`, ~25 LoC). Query params: `?format=bibtex` (default), `?format=ris`, `?format=chicago`. Returns plain text with appropriate Content-Type (`text/plain`, `application/x-bibtex`). Publish-gated. BibTeX template: `@misc{miroshark-{sim_id}, title={MiroShark Simulation: {topic_80chars}}, author={MiroShark Swarm Intelligence Engine}, year={YYYY}, note={Consensus: {direction} at {confidence_pct}\% confidence. {agent_count} agents across {platforms}. Simulated via MiroShark (https://github.com/aaronjmars/MiroShark)}, url={https://miroshark.io/simulation/{sim_id}}}`. RIS template: `TY  - COMP\nTI  - {topic}\nAU  - MiroShark Swarm Intelligence Engine\nPY  - {year}\nUR  - {url}\nN1  - {direction} consensus at {confidence_pct}% confidence\nER  -`. Chicago: `MiroShark Swarm Intelligence Engine. "{topic}." MiroShark simulation, {month} {day}, {year}. https://miroshark.io/simulation/{sim_id}.` Add 6 unit tests: BibTeX output contains sim_id, RIS format starts with TY, Chicago format contains the URL, unknown format returns 400, unpublished sim returns 404, all three formats return different Content-Type headers.
3. Add a "Cite this simulation" button to `Step3Simulation.vue` in the share menu. On click: opens a modal with three tabs (BibTeX / RIS / Chicago), each showing a textarea with the formatted citation string pre-filled from `/api/cite`, with a "Copy" button. Add copy confirmation ("Copied!") with a 2-second timeout. Update `EmbedDialog.vue` to include a "Citation" section: a collapsible block showing the BibTeX for the simulation, with a Copy button. Update `docs/API.md` under a new "Academic Use" section: explain the `/api/cite` endpoint, show curl examples for all three formats, note the CITATION.cff file for repository-level citations. Add the og:citation meta tag to the simulation page head: `<meta name="citation_title" content="{topic}">`, `<meta name="citation_publication_date" content="{date}">`, `<meta name="citation_online_date" content="{date}">` — these are recognized by Google Scholar and similar indexers.

### 5. Python SDK (miroshark-py)

**Type:** Feature / DX
**Effort:** Medium (1-2 days)
**Impact:** Eighteen days until the external-tutorials deadline (0/5). The format most natural for data-driven developer tutorials is a Jupyter notebook: it shows code, output, and narrative in one artifact. A pip-installable `miroshark-py` SDK makes a Jupyter tutorial possible in a single `pip install miroshark` line, with results as pandas DataFrames and matplotlib plots. Tutorial creators who write for Towards Data Science, Medium, or arXiv preprints can embed a real MiroShark simulation into their piece without reading the REST API documentation. The SDK is also the missing piece for the academic citation use case: a researcher who cites MiroShark in a paper needs a stable, versioned, pip-installable artifact to reference — not a raw API endpoint. Beyond tutorials, the SDK lowers the integration ceiling for any developer who wants to run MiroShark programmatically — scripts, CI pipelines, Discord bots. Last suggested Jul 18 (10 days ago), not yet built.

**How:**
1. Create `sdk/python/` directory with standard Python package structure. `pyproject.toml` (package name `miroshark`, version `0.1.0`, requires Python ≥ 3.9, dependencies: `requests>=2.28` only — no heavy deps). `miroshark/__init__.py` exports `MiroShark`, `Simulation`, `SimulationResult`. `miroshark/client.py` (~120 LoC, pure requests): `class MiroShark(base_url, api_key=None, timeout=300)` with methods: `.simulate(topic, agents, rounds, platforms, cost_budget=None) -> Simulation` (POST `/api/simulate`, polls `/api/simulation/{id}/status` until `status=="published"`, returns `Simulation` object); `.get(sim_id) -> Simulation` (GET `/api/simulation/{id}/signal`); `.search(query, limit=10) -> list[Simulation]` (GET `/api/simulation/search`); `.estimate(agents, rounds, platforms) -> dict` (GET `/api/estimate`). `miroshark/models.py` (~80 LoC): `class Simulation` with properties: `.id`, `.topic`, `.consensus_direction`, `.confidence_pct`, `.cost_usd`, `.agent_count`, `.rounds`, `.platforms`, `.signal` (raw dict), `.to_dataframe()` (returns pandas DataFrame of agent-round belief trajectory if pandas is installed, else raises `ImportError` with install hint), `.to_dict()` (raw signal dict), `.cite(format='bibtex')` (calls `/api/simulation/{id}/cite` and returns string). `miroshark/exceptions.py`: `MiroSharkError`, `SimulationError`, `TimeoutError`, `NotFoundError`. `README.md` (SDK-specific, ~80 lines): pip install, 5-line quickstart, `.to_dataframe()` example with pandas, `.cite()` example. Include a `notebooks/` subdirectory with one Jupyter notebook: `quickstart.ipynb` — runs a live simulation on a neutral topic (e.g. "Will remote work remain the default for tech companies?"), prints the consensus result, plots agent belief trajectories with matplotlib, outputs the BibTeX citation. The notebook is designed to run end-to-end in under five minutes on the public MiroShark endpoint — it is the primary tutorial artifact.
2. Add `setup.py` and `MANIFEST.in` for PyPI compatibility. Add a `tests/` directory with 10 unit tests (mock `requests` with `unittest.mock`): client creates correct URL, `simulate()` polls until `published`, `get()` returns `Simulation`, `.to_dict()` returns signal, `.cite()` calls the correct endpoint, `NotFoundError` raised on 404, `TimeoutError` raised after `max_retries`, `.to_dataframe()` raises `ImportError` without pandas, `.search()` returns list of `Simulation`, `.estimate()` returns cost dict. Run `python -m pytest sdk/python/tests/` and confirm all pass. Add CI: create `.github/workflows/sdk-tests.yml` that runs the SDK tests on push to any branch touching `sdk/python/` — this guards against API changes silently breaking the SDK.
3. Update `README.md` at the root: add "Python SDK" to the Features section (`pip install miroshark` one-liner), add a "Quickstart (Python)" code block below the CLI quickstart showing the 5-line SDK usage, add a "Python SDK" badge (`[![PyPI](https://img.shields.io/pypi/v/miroshark)](https://pypi.org/project/miroshark/)`). Add `sdk/python/` to `docs/FEATURES.md`. ## Selection Rationale

All five ideas target the active crises (4-day community-PR deadline, 18-day tutorial deadline, 22-day social silence) with a range of time-to-impact.

- **Good First Issue Sprint (#1)** — The Aug 1 deadline is four days away. No feature build will generate five community PRs in four days; creating eight labeled issues that fork holders can close in under two hours is the only intervention with that time constant. The `gh issue create` command doesn't require GH_GLOBAL — it runs against the watched repo with the native token. The contributor leaderboard section in README creates permanent social credit to motivate the conversion. This is the most urgent idea in this list.

- **Show HN Launch Kit (#2)** — Zero external tutorials in 18 days requires reaching the audience that writes them. HN's senior engineering readership is that audience. A front-page Show HN drives hundreds of curious developers to try MiroShark in a 48-hour window — statistically, several will document what they find. The kit also produces the canonical "what is MiroShark in 300 words" text that any fork holder can paste into their own tutorial or README fork. The demo script is independently useful for the community call hyperstition.

- **Spanish (ES) Locale (#3)** — 35 days, 35 days, 35 days. The 5-language hyperstition closes at one PR. Spanish is the second-largest developer language community on GitHub and the highest-volume tutorial production community among the remaining unbuilt locales. The dictionary-only pattern is proven at three languages. This is the most mechanical idea in this list — high certainty of implementation success once GH_GLOBAL unblocks.

- **Academic Citation Helper (#4)** — The CITATION.cff file is a one-time commit that permanently activates GitHub's "Cite this repository" sidebar button for every researcher who lands on the repo page. The `/api/cite` endpoint adds per-result citations. The og:citation meta tags make individual simulation results discoverable by Google Scholar. - **Python SDK (#5)** — The external tutorial deadline (18 days, 0/5) has a specific bottleneck: no pip-installable package means tutorial creators must write their own API wrapper before they can demonstrate anything. `pip install miroshark; client.simulate(...)` removes that barrier. The SDK also makes MiroShark formally packageable for the PyPI citation that academic papers need.
