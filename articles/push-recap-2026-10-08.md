### CI/CD: Ruff Linter Added
**Summary:** A new Python lint job was added to the CI pipeline using ruff, pinned at 0.15.11. The ruleset is intentionally narrow — only bug-catching rules (syntax errors, undefined names, unused imports/variables), no formatting enforcement. The commit also fixed the four issues ruff found in existing code.

**Commits:**
- `13279cb` — chore: add ruff lint to CI (#318)
  - New file `ruff.toml`: Config targeting py311, excluding `frontend/`, selecting rules E9/F63/F7/F82/F401/F841 (+8 lines)
  - Changed `.github/workflows/tests.yml`: Added `lint` job — checkout, install ruff==0.15.11, run `ruff check .` (+19 lines)
  - Changed `backend/wonderwall/environment/env.py`: Added `TYPE_CHECKING` import guard for `BasePlatform` and `SimulationConfig` — these were used in type hints but not imported, causing F82 (undefined name) violations (+4/-1 lines)
  - Changed `scripts/scan_i18n.py`: Removed unused `ast` import (F401) and unused `call_text` variable (F841) (+0/-2 lines)

**Impact:** Every future push now runs a lightweight Python lint pass. The narrow rule selection means it won't generate noisy style warnings — only catches actual bugs. The `TYPE_CHECKING` fix in env.py is the most meaningful: those missing imports could have caused runtime `NameError` if the type hints were ever evaluated at runtime (e.g., by Pydantic or a serialization library).
