### 1. Simulation ZIP Bundle Export

**Type:** Feature / DX
**Effort:** Small (hours)
**Impact:** Currently collecting all simulation data requires 3–4 separate API calls: `signal.json`, `trajectory.json`, `actions.jsonl`, and (after the Oct 4 batch) `digest.md`. `GET /api/simulation/{id}/bundle.zip` packages all four files plus a `README.md` (bundle manifest + simulation URL + MiroShark attribution) into a single ZIP archive. A researcher who wants all simulation data for offline analysis currently has to script a multi-step fetch loop. `bundle.zip` collapses that to one `curl` command. Distinct from: Air-Gap Bundle (Sep 28 — a full offline-runnable distribution with the engine itself, not just data), Jupyter Notebook Export (Oct 2 — an executable `.ipynb` with analysis cells). This is the "send me the raw data" archive — output artifacts only, nothing to execute.

**How:**
1. Create `backend/app/api/bundle.py` (~80 LoC, pure stdlib `zipfile` + `io`). `GET /api/simulation/{id}/bundle.zip`. Publish-gated (returns 404 for unpublished). Reads `signal.json`, `trajectory.json`, `actions.jsonl` from the simulation directory. Generates `digest.md` inline (same Unicode belief-bar logic from the Oct 4 Digest idea, or reads from `.digest-cache/{id}.md` if already built). Generates `README.md`: 5 lines — bundle contents list, simulation topic + direction pulled from `signal.json`, simulation URL (`{BASE_URL}/simulation/{id}`), MiroShark attribution link, generation timestamp. Builds ZIP in memory using `zipfile.ZipFile(io.BytesIO(), 'w', zipfile.ZIP_DEFLATED)`. Adds all 5 files. Returns bytes with `Content-Type: application/zip`, `Content-Disposition: attachment; filename="miroshark-{simulation_id}.zip"`. No disk cache (files are small; build on demand). Add 3 unit tests: 404 for unpublished; response starts with ZIP magic bytes `PK\x03\x04`; namelist contains exactly 5 entries.

2. Add `GET /api/simulation/{id}/bundle.zip` to `surfaces_catalog.py` (type: `export`) and OpenAPI schema noting `application/zip` content type with a file manifest table. Register route in `backend/app/main.py`. Add a "Download Bundle (.zip)" button to the Step 3 share panel, alongside existing export controls. Include in `EmbedDialog.vue` under "Export" as a `curl` example: `curl "{BASE_URL}/api/simulation/{id}/bundle.zip" -o simulation.zip`. Add to `docs/API.md` under "Export Endpoints" with the manifest: `signal.json` (aggregate result), `trajectory.json` (per-round belief data), `actions.jsonl` (per-agent actions), `digest.md` (human-readable summary), `README.md` (bundle guide). Add to `docs/FEATURES.md`.

3. Add a `?include=` query param: `all` (default — all 5 files), `data` (`signal.json` + `trajectory.json` + `actions.jsonl`, no digest or README), `minimal` (`signal.json` + `README.md` only). Implement via a conditional file list built before the ZIP loop — no structural change to the ZIP logic. Add 2 unit tests: `?include=data` namelist has 3 entries and no README; `?include=minimal` namelist has exactly 2 entries. Document both values in `docs/API.md` with use-case notes: "`data` for pipeline ingestion (skip human-readable files), `minimal` for quick metadata snapshots." Add `?format=flat` vs `?format=nested` path param: `flat` (default — all files at root level in ZIP), `nested` (files in a `miroshark-{id}/` subdirectory — useful when unzipping multiple bundles into the same directory without collision). 1 unit test: `?format=nested` namelist entries all start with `miroshark-{id}/`.

### 2. Per-Agent Career History API

**Type:** Feature / Analytics
**Effort:** Medium (1-2 days)
**Impact:** The Archetype Atlas (Jun 6) shows aggregate stats per archetype: average bullish %, flip rate, influence score pooled across all simulations. What it cannot show is the *longitudinal arc* of a specific archetype: "has Contrarian_Analyst shifted more bullish in October vs. September?" `GET /api/agents/{archetype}/career` returns a chronological list of every simulation where that archetype appeared — with per-sim stance, influence score, topic, and direction — sorted by `published_at` descending. A researcher building a model on MiroShark data can use this endpoint to construct a time-series view of an archetype's behavior across topics and across time. Distinct from: Archetype Atlas (cross-sim aggregate stats only, no per-sim history), Agent Mention Network (Jun 12 — who @-mentioned whom *within* a single sim), Stance Flip Report (Jun 13 — stance changes *within* a single sim). This is **cross-simulation, per-archetype longitudinal data** — a career record, not a snapshot.

**How:**
1. Create `backend/app/services/agent_career_service.py` (~180 LoC, pure stdlib). Class `AgentCareerService`. Index build: scan all published simulation directories; for each sim read `signal.json` and extract entries from `top_agents` where `name` matches the requested archetype (case-insensitive, normalized: lowercase + strip). Collect `[{simulation_id, topic, direction, agent_stance, influence_score, published_at}]`. Cache per-archetype to `.agent-career-cache/{archetype_normalized}.json` with 15-minute mtime TTL — normalize archetype name by lowercasing and replacing spaces with underscores for the cache filename. Method `get_career(archetype: str, limit: int = 50) -> dict` returns `{archetype, total_appearances, avg_influence_score, stance_distribution: {BULLISH, NEUTRAL, BEARISH}, recent_appearances: [...limit entries...]}`. `stance_distribution` is raw counts, not percentages — let callers compute ratios. Add 4 unit tests: unknown archetype returns 404 response code; results sorted by `published_at` desc; `stance_distribution` counts sum to `total_appearances`; `limit` param clamps at `[1, 100]`.

2. Add `GET /api/agents/{archetype}/career` endpoint in `backend/app/api/`. Path param: `{archetype}` (URL-decoded, case-insensitive). Query params: `limit` (int, default 50, clamp [1, 100]). Returns `{archetype, total_appearances, avg_influence_score, stance_distribution, recent_appearances}`. Returns 404 with `{"detail": "archetype not found in corpus"}` if `total_appearances == 0`. Cache-Control: `max-age=900` (15 min, matching disk cache TTL). Add to `surfaces_catalog.py` (type: `analytics`) and OpenAPI with `AgentCareerResponse` and `CareerAppearance` schemas. Add 2 integration tests: correct response shape for a known archetype; 404 for unknown archetype string. Register route in `main.py`. Add to `docs/API.md` under a new "Agent Analytics" section with a note: "Archetype names are normalized — 'Contrarian_Analyst' and 'contrarian analyst' resolve to the same record." Add to `docs/FEATURES.md` under "Analytics."

3. Surface in the existing Archetype Atlas frontend at `/archetypes`. On each archetype card's expand, add a "Career" tab alongside existing aggregate stats. Fetches `GET /api/agents/{archetype_name}/career?limit=20` lazily on first tab activation (not on page load). Renders a timeline list: each entry shows topic (truncated to 40 chars + ellipsis), direction badge chip (color-coded), influence score as a short bar (0–1 scale), and relative date ("3 days ago" / "2 weeks ago"). Clicking an entry links to `{BASE_URL}/simulation/{simulation_id}`. If `total_appearances > 20`, render a "View all {N} appearances →" link pointing to the raw API endpoint URL — so power users can pull the full history without a frontend page. Below the timeline, show the `stance_distribution` as three stat tiles (BULLISH / NEUTRAL / BEARISH count). Bilingual (EN/ZH-CN). No new nav required — the career data surfaces exactly where users already browse archetype aggregate stats.

### 5. Simulation Watchlist Collections

**Type:** Feature
**Effort:** Medium (1-2 days)
**Impact:** A researcher running 10 BTC simulations at different timestamps has no way to group them. An analyst building a report on "AI market forecasts for Q4 2026" has no way to save their curated set of relevant simulations. API-key authenticated watchlist endpoints: `POST /api/watchlists` (create a named collection), `POST /api/watchlists/{id}/simulations` (add a simulation), `GET /api/watchlists/{id}` (get collection with per-sim summaries), `DELETE /api/watchlists/{id}/simulations/{sim_id}` (remove one). Watchlists are publicly readable by URL — no auth required to read; API key required to write. A researcher shares the watchlist URL in a report: all simulations, live data, one link. Distinct from: Simulation Comparison API (Sep 28 — side-by-side diff of exactly two sims), Full-Text Search (Jun 14 — corpus-wide search by query), Similar Simulations Discovery (Sep 30 — automatic adjacency from a single sim). This is **persistent, user-curated collections**: arbitrary sets, named by the creator, shareable by URL.

**How:**
1. Create `backend/app/services/watchlist_service.py` (~200 LoC, pure stdlib). Storage: a directory `.watchlists/` at the repo root. Each watchlist stored as `.watchlists/{watchlist_id}.json` (UUID v4, hex-only, 32 chars). Schema: `{id, name, created_at, api_key_hash: sha256(api_key)[0:16], simulation_ids: []}`. Max 50 simulations per watchlist (return 422 on exceed). Max 10 watchlists per API key (sha256 prefix dedup). Methods: `create(name: str, api_key: str) -> dict`, `add_simulation(watchlist_id: str, simulation_id: str, api_key: str) -> dict`, `get(watchlist_id: str) -> dict` (returns watchlist metadata + per-sim summary from `signal.json` for each simulation_id — skips simulations that are no longer published), `remove_simulation(watchlist_id: str, simulation_id: str, api_key: str) -> None`. Auth: all mutating operations verify `sha256(api_key)[0:16] == watchlist.api_key_hash`. No full API key stored anywhere. Add 5 unit tests: create returns valid UUID; add simulation increments simulation_ids; get returns per-sim summaries; remove decrements; auth mismatch returns 403.

2. Add four routes in `backend/app/api/watchlists.py`: `POST /api/watchlists` (auth required: `X-API-Key` header), `POST /api/watchlists/{id}/simulations` (body: `{simulation_id}`, auth required), `GET /api/watchlists/{id}` (public, no auth), `DELETE /api/watchlists/{id}/simulations/{sim_id}` (auth required). Returns for `GET`: `{id, name, created_at, simulation_count, simulations: [{simulation_id, topic, direction, confidence_pct, published_at}]}` — per-sim summary pulled from cached `signal.json`. Cache-Control on GET: `max-age=60` (1 minute — collections update rarely). Return 404 for unknown watchlist IDs, 403 for auth failures, 422 for capacity limits. Add to `surfaces_catalog.py` (type: `collections`), OpenAPI with `WatchlistResponse`, `WatchlistSummary`, `SimulationSummary`. Register all four routes in `main.py`. Add to `docs/API.md` under new "Collections" section with auth instructions. Add to `docs/FEATURES.md`.

3. Add a "Save to Watchlist" button to the Step 3 share panel. On click, opens a modal: either "Create new watchlist" (text input for name, calls `POST /api/watchlists` with an API key from localStorage) or "Add to existing" (dropdown of watchlists retrieved by API key from localStorage). After saving, shows the watchlist URL with a "Copy Link" button. If no API key is stored, show a prompt to generate one via the existing API key flow. Also add `GET /api/watchlists/{id}` data to the `EmbedDialog.vue` — under "Share," show the watchlist URL if the simulation is already part of any watchlist (check by scanning `.watchlists/*.json` for the simulation_id). Add a `GET /api/watchlists` endpoint (auth required) that returns all watchlists for a given API key — limited to the 10-per-key cap — for the "Add to existing" dropdown to populate. Add 2 integration tests: GET `/api/watchlists/{id}` after adding a simulation returns that simulation in the list; GET on an unknown ID returns 404. Bilingual (EN/ZH-CN) for the modal and share panel.

## Selection Rationale

Five ideas for Day 6 of Hacktoberfest, 90-day silence, and the ongoing GH_GLOBAL-blocked reality.

- **Simulation ZIP Bundle (#1)** — One `curl` command instead of four. Data portability is the lowest-friction path for researchers and integrators who want everything offline. The `?include=` param makes it useful for both pipeline ingestion and casual archive. Distinct from the executable Air-Gap Bundle (Sep 28) and the analytical Jupyter Notebook (Oct 2) — this is just the raw data, all of it, now.

- **Per-Agent Career History (#2)** — Extends the existing Archetype Atlas (Jun 6) from a snapshot to a timeline. The Atlas already did the hard work of building the archetype index; this endpoint reads the same data and adds temporal ordering. The Archetype Atlas frontend gets a "Career" tab with no new navigation required. For researchers building models on 8,000+ MiroShark simulations, longitudinal archetype behavior is the next natural query after aggregate stats.

- **Simulation Rich Link Preview (#3)** — 90 days of silence means no one is composing captions. But simulation URLs are still being shared by users. Every shared link that auto-renders a rich unfurl card instead of a bare URL does work without a human. The crawler-aware HTML injection (30 LoC in the backend) and the minimal og-image (600×314 Pillow PNG) are the only two moving parts. No external service, no social API, no auth. Pure passive distribution multiplier.

- **token-movers Skill Repair (#4)** — The skill has failed 3+ times in 14 days. health issue #182 is open with 7 comments. token-movers feeds heartbeat, memory-flush, and project-lens — repeated failures generate cascading health noise across the entire aeon stack. This is the highest-priority operational repair available today. Fixing it now prevents another 14-day failure window.

- **Simulation Watchlist Collections (#5)** — The only prior idea that addressed user-curated sets was Simulation Comparison API (Sep 28 — two-sim side-by-side) and Webhook Subscription System (general event webhooks). Neither supports arbitrary named collections shared by URL. Watchlists fill the gap between single-simulation sharing and corpus-level search: a researcher's curated set of 10 relevant simulations, shareable as one URL. The auth model (API key hash, no full key stored) keeps it stateless and auditable.
