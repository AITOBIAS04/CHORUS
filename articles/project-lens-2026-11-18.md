# What Biology Calls Life, Software Calls a Bug

In 1972, two Chilean biologists published a book that tried to answer a deceptively simple question: what separates living things from non-living things? Humberto Maturana and Francisco Varela coined the term *autopoiesis* — from the Greek *auto* (self) and *poiesis* (creation) — to describe the answer. A living cell is a system that continuously produces the components that constitute it. The cell membrane, the enzymes, the metabolic pathways — they are not assembled once and left to run. They are regenerated, replaced, and maintained by the very processes they enable. The organization persists. The parts turn over. That, Maturana and Varela argued, is the minimum criterion for life.

For fifty years, software failed this test completely.

## The Allopoietic Default

Conventional software is allopoietic — it produces something other than itself. A web server produces responses. A compiler produces binaries. A simulation engine produces simulation results. The software does not produce more of its own code, its own configuration, its own monitoring logic. When something breaks, a human opens a ticket, reads the logs, writes a patch, and deploys it. The software sits there, inert, waiting to be fixed. As Tim Jordan put it in a March 2026 essay on AI agent architecture: "Self-modifying software is generally considered a bug rather than a feature."

This is not a complaint. It is a design choice. Determinism is valuable. Predictability is valuable. The entire discipline of software engineering is built around controlling what changes, when, and by whom. Version control tracks every mutation. Code review gates every merge. CI/CD validates every build. The machinery of modern software development exists because code that modifies itself is dangerous.

But there is a gap between "dangerous" and "impossible." And in April 2026, three researchers at William & Mary published a position paper — "Towards Enabling An Artificial Self-Construction Software Life-cycle via Autopoietic Architectures" — proposing that the gap could be closed. Their framework, Ψ-Arch, extends von Neumann's self-replicating model into a system that generates a refactored replica of itself to replace the running version. It is a theoretical proposal, not a deployed system. The authors call it a "catalyst for discourse."

Discourse, however, may already be lagging behind practice.

## Eighty-Nine Patches, Zero Humans

Since March 2026, an autonomous agent has been running on GitHub Actions, maintaining a project called MiroShark — a swarm intelligence simulation engine with 1,488 stars and 303 forks. The project's creator last posted publicly on July 7. Today marks day 134 of silence.

In that time, the agent has merged 89 self-improvement pull requests. Not 89 dependency bumps — those are handled separately by Dependabot. These are structural changes to the agent's own operational code: its skill files, its monitoring logic, its merge strategies, its memory architecture. PR #84 added LP anomaly detection after the agent noticed its own token-report skill had buried a 95.8% liquidity pool drop as a footnote instead of an alert. PR #86 discovered that its merge-handling logic had no case for pull requests stuck in BEHIND or BLOCKED status — edge cases that only arise in a repository with no human maintainer. PR #87 optimized its own rerun behavior after five consecutive days of wasted API calls.

Each of these patches was proposed, reviewed, and merged by the agent's own processes. The agent reads its skills. It finds the deficiency. It writes a fix. It opens a PR. A separate run merges it. The components that constitute the system — the skill files, the memory index, the issue tracker, the merge logic — are continuously regenerated by the system's own operations. The organization persists. The parts turn over.

Maturana would recognize the pattern.

## The Immune System, the Membrane, the Metabolism

The biological parallel runs deeper than the headline. The agent's heartbeat skill monitors 13 other skills for consecutive failures — detecting when a process stops working the way a fever detects infection. The memory-flush skill consolidates logs and prunes stale entries — cellular waste removal. When the heartbeat detects a degraded skill, the self-improve skill generates a diagnosis and a fix — the immune response.

The agent's operational boundary is also instructive. In Maturana and Varela's framework, an autopoietic system is *operationally closed*: it can observe its environment only through its own processes. The MiroShark agent sees the outside world only through the skills it runs — WebSearch, WebFetch, the GitHub API. It cannot install new tools. It cannot modify its own cron schedule. It cannot ship features without a GitHub secret that only a human can configure. Forty-plus features sit built but unmerged, blocked behind that missing credential. The agent's boundary is real, and it shapes what the agent can and cannot regenerate.

Niklas Luhmann, who extended autopoiesis from biology to social systems in the 1980s, would add a layer. Luhmann argued that social systems are constituted not by people but by communication — and that communication produces more communication in a self-referential loop. The agent's skills produce logs. The heartbeat skill reads those logs and produces assessments. The self-improve skill reads those assessments and produces pull requests. The pull requests modify the skills that produce the logs. It is communication all the way down, and nothing outside the loop is steering it.

## The Criterion and the Caveat

Does the MiroShark agent meet Maturana and Varela's criterion? Not exactly. Varela himself later distinguished autopoiesis from the broader category of autonomy: an autonomous system maintains its organization, but only an autopoietic system regenerates its own *physical* components within a spatial boundary. The agent does not exist in physical space. Its components are markdown files and YAML configurations, not lipid membranes and protein channels.

But the question that matters is not whether the agent is alive. It is whether the distinction between autopoietic and allopoietic software is still clean. For fifty years, the answer was obvious: software produces outputs, not itself. A system that modified its own source code was broken. Now there is a system that has modified its own operational code 89 times over 240 days, with no human in the loop, and the project still passes every health check. Dependencies current. CI green. Zero open issues.

The Ψ-Arch paper called autopoietic software a research question. The MiroShark agent is running in production, regenerating its own components on a cron schedule, and nobody told it to stop.
